# 城线 · Ubuntu 部署指南

使用 Ubuntu 24.04 LTS。部署包包含 2026 年 11 月 22 日当前工作区源码，全年默认按 5 月、7 月、10 月投放。Rust 二进制在服务器编译，前端随二进制运行。Node.js 和 Chromium 用于平台取数和线路图截图。以下示例请替换 SSH 用户、服务器地址及域名。

## 1. 从 Windows 上传源码和现有配置

用平时启动城线的 Windows 账号，在原项目目录执行。导出脚本沿用现有启动逻辑，读取本机配置及 Windows 加密保存的三项密钥，生成受权限保护的暂存目录。现有 Agent 地址、模型、推理强度、协作方式、平台接口、红豆 OAuth2、红豆预存账号和刊例均可沿用。导出不会启动或重启本机工作台。

~~~powershell
$server = 'ubuntu@你的云服务器'
$transfer = .\scripts\start-cityline.ps1 -ExportUbuntu
ssh $server 'umask 077 && mkdir -p "$HOME/.cityline-transfer" && chmod 700 "$HOME/.cityline-transfer"'
scp .\output\Cityline-Agent-Ubuntu-20261122.tar.gz .\output\Cityline-Agent-Ubuntu-20261122.tar.gz.sha256 "${server}:"
scp "$transfer/cityline.env" "$transfer/settings.json" "$transfer/tariff.xlsx" "${server}:.cityline-transfer/"
~~~

如果导出目录内有 OIDC 或飞书的 CA 文件，也通过同一 SSH 通道上传。源码包可分发，配置暂存目录须按凭据保管。部署验收通过后清理两端暂存副本。

从开源仓库全新部署时，在 Ubuntu 上执行 `git clone https://github.com/XinTycd/Cityline-Agent.git ~/Cityline-Agent-Ubuntu-20261122`。第 2 节可跳过校验和解压压缩包的两条命令。把 `.env.example` 复制到仅当前运维用户可读的 `~/.cityline-transfer/cityline.env`，设定 `ACCEPTANCE_RUST_PORT=3412` 和 `ACCEPTANCE_RUST_DATA=/var/lib/cityline/cityline.sqlite`。先留空 `CITYLINE_PUBLIC_ORIGIN`。仅运行合成样例时，模型与平台配置均可留空。正式取数时，从有权使用的平台取得对应配置，并将授权刊例上传至暂存目录的 `tariff.xlsx`，令 `CITYLINE_CONTEST_TARIFF=/etc/cityline/tariff.xlsx`。保存配置文件为 UTF-8。

## 2. 安装依赖和编译

SSH 登录 Ubuntu，按顺序执行。首次安装 Rust 及 Node.js 时使用官方发行来源，编译依赖和浏览器版本由项目锁文件确定。

~~~bash
sudo apt update
sudo apt install -y build-essential pkg-config libssl-dev curl ca-certificates xz-utils python3 sqlite3
rustup_file=$(mktemp)
curl -fsS --proto '=https' https://sh.rustup.rs -o "$rustup_file"
sh "$rustup_file" -y --profile minimal --default-toolchain stable
. "$HOME/.cargo/env"

case "$(dpkg --print-architecture)" in
  amd64) node_arch=x64 ;;
  arm64) node_arch=arm64 ;;
  *) echo "请选用 amd64 或 arm64 Ubuntu" >&2; exit 1 ;;
esac
node_tmp=$(mktemp -d)
node_base=https://nodejs.org/dist/latest-v24.x
curl -fsS "$node_base/SHASUMS256.txt" -o "$node_tmp/SHASUMS256.txt"
node_file=$(awk -v arch="$node_arch" '$2 ~ ("^node-v24[.][0-9]+[.][0-9]+-linux-" arch "[.]tar[.]xz$") { print $2 }' "$node_tmp/SHASUMS256.txt")
test -n "$node_file" || exit 1
curl -fsS "$node_base/$node_file" -o "$node_tmp/$node_file"
(cd "$node_tmp" && awk -v file="$node_file" '$2 == file' SHASUMS256.txt | sha256sum -c -) || exit 1
node_dir="/opt/cityline/${node_file%.tar.xz}"
sudo install -d -m 0755 "$node_dir"
sudo tar --no-same-owner --strip-components=1 -xJf "$node_tmp/$node_file" -C "$node_dir"
sudo ln -sfn "$node_dir" /opt/cityline/node
export PATH="/opt/cityline/node/bin:$PATH"

cd "$HOME"
sha256sum -c Cityline-Agent-Ubuntu-20261122.tar.gz.sha256 || exit 1
tar -xzf Cityline-Agent-Ubuntu-20261122.tar.gz
cd Cityline-Agent-Ubuntu-20261122
npm ci --ignore-scripts
cargo +stable test --locked --manifest-path apps/acceptance-rust/Cargo.toml
cargo +stable build --release --locked --manifest-path apps/acceptance-rust/Cargo.toml
node node_modules/playwright-core/cli.js install-deps chromium
PLAYWRIGHT_BROWSERS_PATH="$PWD/.playwright" node node_modules/playwright-core/cli.js install chromium
~~~

每条命令成功后再继续。更新 Playwright 后重新安装对应版的 Chromium。[Rust 安装](https://rust-lang.org/tools/install/) · [Node.js 24 发行目录](https://nodejs.org/dist/latest-v24.x/) · [Playwright 浏览器依赖](https://playwright.dev/docs/browsers)

## 3. 安装服务并导入配置

以下为首次安装。目标服务器已有城线时，先备份原配置和数据库，再按第 7 节升级。

~~~bash
cd "$HOME/Cityline-Agent-Ubuntu-20261122"
getent passwd cityline >/dev/null || sudo useradd --system --user-group --home-dir /var/lib/cityline --shell /usr/sbin/nologin cityline
release=/opt/cityline/releases/20261122
sudo install -d -m 0755 "$release/bin"
sudo install -m 0755 apps/acceptance-rust/target/release/hackson-acceptance "$release/bin/"
sudo cp -a scripts node_modules .playwright deploy "$release/"
sudo chown -R root:root "$release"
sudo chmod -R a+rX,go-w "$release"
sudo ln -sfn "$release" /opt/cityline/current

sudo install -d -o root -g cityline -m 0750 /etc/cityline
sudo install -o root -g cityline -m 0640 "$HOME/.cityline-transfer/cityline.env" /etc/cityline/cityline.env
if test -f "$HOME/.cityline-transfer/settings.json"; then
  sudo install -o root -g cityline -m 0640 "$HOME/.cityline-transfer/settings.json" /etc/cityline/workspace-settings.json
fi
if test -f "$HOME/.cityline-transfer/tariff.xlsx"; then
  sudo install -o root -g cityline -m 0640 "$HOME/.cityline-transfer/tariff.xlsx" /etc/cityline/tariff.xlsx
fi
for file in oidc-ca.pem feishu-ca.pem; do
  if test -f "$HOME/.cityline-transfer/$file"; then
    sudo install -o root -g cityline -m 0640 "$HOME/.cityline-transfer/$file" "/etc/cityline/$file"
  fi
done
sudo install -m 0644 deploy/ubuntu/cityline.service /etc/systemd/system/cityline.service

# 本机 3412 已在用，云端初始化用 13412。
sudo install -d -m 0755 /etc/systemd/system/cityline.service.d
printf '[Service]\nEnvironment=ACCEPTANCE_RUST_PORT=13412\n' | sudo tee /etc/systemd/system/cityline.service.d/bootstrap.conf >/dev/null
sudo systemctl daemon-reload
sudo systemctl start cityline
curl -fsS --retry 10 --retry-connrefused http://127.0.0.1:13412/overview >/dev/null
sudo systemctl stop cityline
if sudo test -f /etc/cityline/workspace-settings.json; then
  sudo -u cityline python3 "$release/deploy/ubuntu/transfer-settings.py" import /var/lib/cityline/cityline.sqlite /etc/cityline/workspace-settings.json
fi
sudo systemctl enable --now cityline
~~~

服务以专用账号运行，配置在 `/etc/cityline`，数据库、报告和取数归档在 `/var/lib/cityline`。本流程迁入 Agent 设置和站点品牌，云端从空任务库开始。[systemd 执行环境](https://manpages.ubuntu.com/manpages/noble/man5/systemd.exec.5.html)

## 4. 开启工作台登录和公网 HTTPS

在 Windows 打开 SSH 隧道。在浏览器访问 `http://127.0.0.1:13412/settings?tab=login`，开启「本地登录服务」，设置独立管理员账号及至少 12 位密码，退出后重新登录一次。

~~~powershell
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:13412:127.0.0.1:13412 ubuntu@你的云服务器
~~~

只有自己使用时，可以继续通过 SSH 隧道访问。开放公网时，先把域名解析到云服务器，放通安全组的 80 和 443 端口。SSH 端口限制到运维来源。应用端口和授权桌面端口保持回环监听。

在 Ubuntu 上用 `sudoedit` 设置 `/etc/cityline/cityline.env` 的 `CITYLINE_PUBLIC_ORIGIN` 为实际的 HTTPS 站点根地址，末尾省略路径。用包内 `deploy/ubuntu/Caddyfile.example` 的站点块替换占位域名。如已有其他站点，把站点块合并进原配置。

~~~bash
sudoedit /etc/cityline/cityline.env
sudo rm /etc/systemd/system/cityline.service.d/bootstrap.conf
sudo systemctl daemon-reload
sudo systemctl restart cityline
sudo apt install -y caddy
sudoedit /etc/caddy/Caddyfile
sudo caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
sudo systemctl reload caddy
~~~

从浏览器打开域名，核验证书、跳转和管理员登录。Caddy 转发到 `127.0.0.1:3412` 并保留原 Host。若使用 OIDC 或飞书，向身份提供方登记「系统设置」显示的公网 HTTPS 回调。[Caddy 自动 HTTPS](https://caddyserver.com/docs/automatic-https) · [Caddy 反向代理](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)

## 5. 确认平台授权和线路图

红豆使用迁入的预存账号自动换取令牌。新云首次访问或会话过期时，仍需操作员在官方登录页验证。Linux 使用 Playwright 配套 Chromium。为可见的授权窗口安装可通过 SSH 访问的桌面。先等正在执行的提案结束。

~~~bash
sudo apt install -y tigervnc-standalone-server tigervnc-tools openbox xauth xfonts-base
sudo install -d -o cityline -g cityline -m 0700 /var/lib/cityline/.vnc
sudo -u cityline -H tigervncpasswd /var/lib/cityline/.vnc/passwd
sudo install -m 0644 /opt/cityline/current/deploy/ubuntu/cityline-desktop.service /etc/systemd/system/
sudo install -m 0644 /opt/cityline/current/deploy/ubuntu/desktop.conf /etc/systemd/system/cityline.service.d/desktop.conf
sudo systemctl daemon-reload
sudo systemctl restart cityline
sudo systemctl status cityline-desktop --no-pager
sudo ss -lntp
~~~

在 Windows 新开终端建立隧道。TigerVNC Viewer 连接 `127.0.0.1::5908`。回到工作台提交正式任务，在云服务器桌面打开的浏览器中完成新云登录。5908 仅在服务器回环监听。[Ubuntu TigerVNC 参数](https://manpages.ubuntu.com/manpages/noble/man1/tigervncserver.1.html)

~~~powershell
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:5908:127.0.0.1:5908 ubuntu@你的云服务器
~~~

## 6. 验收和常见故障

1. 用 `sudo systemctl status cityline --no-pager` 检查服务，用 `sudo journalctl -u cityline -n 100 --no-pager` 查看日志。
2. 登录工作台，运行合成样例。核对 5、7、10 月，下载并离线打开 A/B HTML。
3. 在「Agent 配置」执行连接测试，再提交正式任务。确认三段库存、自动红豆授权、新云取数和线路图。数据完整性与平台访问以云服务器实际联调为准。
4. 公网返回 403 时，核对登录已开启、配置的 HTTPS 域名与访问域名一致、Caddy 保留原 Host。平台浏览器打不开时，检查 Chromium 下载目录、桌面状态及服务覆写。平台认证失败时，核对云服务器的出口网络、平台白名单及授权状态。

## 7. 备份、升级与回滚

选择空闲时段，停止服务后备份。备份中含业务数据及配置，存入受限存储。

~~~bash
sudo systemctl stop cityline
backup="/var/backups/cityline-$(date +%Y%m%d-%H%M%S)"
sudo install -d -m 0700 "$backup"
sudo sqlite3 /var/lib/cityline/cityline.sqlite ".backup $backup/cityline.sqlite"
sudo cp -a /etc/cityline "$backup/config"
if sudo test -d /var/lib/cityline/browser-refresh; then
  sudo cp -a /var/lib/cityline/browser-refresh "$backup/"
fi
readlink -f /opt/cityline/current
~~~

将新版编译安装到不同的版本目录，保留现有私有配置、数据库和桌面覆写。切换 `/opt/cityline/current`，启动服务并复验。若要回滚，停服，将链接切回已记录的旧版本再启动。若新版已执行不兼容的数据库迁移，先保留新版数据库副本，再在停服状态恢复旧版备份及其文件所有权。
